# 📈 로지스틱 익스체인지 — 수송 주식시장 실시간 웹앱

중3 「수송 기술의 활용」 2차시용 실시간 멀티플레이 주식시장 게임.
교사 컴퓨터(전자칠판)가 진행·리더보드를, 모둠 태블릿 6대가 매매를 맡는다.
뉴스 3장 중 시장을 움직이는 **진짜 뉴스 1장**을 판별하고, 수송 수단 6종의
특징(속도·수송량·비용·거리·날씨·접근성)으로 등락을 예측해 매매한다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 역할 선택 (선생님 / 모둠) |
| `teacher.html` | 교사 화면 — 방 개설, 라운드 진행, 리더보드, 최종 결과 |
| `student.html` | 모둠 화면 — 입장, 매매, 결과, 최종 성적표 |
| `game-data.js` | **뉴스 30장(진짜 10 + 더미 20)·종목·해설 — 교사가 직접 수정 가능** |
| `realtime.js` | Firebase 공통 모듈 (다른 수업 게임에 재사용 가능) |
| `config.example.js` | Firebase 설정 예시 → 복사해서 `config.js` 로 |
| `style.css` | 공통 스타일 (다크 트레이딩 테마) |

> `config.js` 가 없어도 앱은 동작한다 — 자동으로 **오프라인(뉴스 코드) 모드**가 된다.

## 1. Firebase 세팅 (15분 가이드)

1. https://console.firebase.google.com 접속 → 구글 계정 로그인 → **[프로젝트 추가]**
   - 이름 예: `class-games` → 애널리틱스는 **꺼도 됨** → 생성 (약 1분)
2. 왼쪽 메뉴 **빌드 → Realtime Database** → **[데이터베이스 만들기]**
   - 위치: `asia-southeast1(싱가포르)` 권장 → **테스트 모드로 시작** 선택
3. **규칙** 탭에서 아래로 교체 후 [게시] (교실용 — 방은 수업 후 삭제하므로 전체 허용):
   ```json
   {
     "rules": {
       "rooms": { ".read": true, ".write": true }
     }
   }
   ```
4. 프로젝트 개요 옆 **⚙️ → 프로젝트 설정 → 일반** → 아래 "내 앱"에서 **웹 앱(</>) 추가**
   - 앱 닉네임 아무거나 → 등록 → `firebaseConfig` 값이 보인다
5. 이 폴더의 `config.example.js` 를 복사해 **`config.js`** 로 저장하고
   `apiKey`, `authDomain`, `databaseURL`, `projectId` 를 붙여넣는다.
   - ⚠️ `databaseURL` 이 안 보이면 Realtime Database 페이지 상단의
     `https://….firebasedatabase.app` 주소를 복사해 넣을 것.
6. 로컬 테스트: 이 폴더에서 `python -m http.server 8000` (또는 VS Code Live Server)
   → `http://localhost:8000` 접속 → 선생님 화면에서 [새 게임] → 다른 브라우저 탭으로
   모둠 화면 입장 테스트.

## 2. Vercel 배포 (5분)

1. 이 폴더를 GitHub 저장소로 푸시 (`config.js` 포함 — 교실용이라 공개돼도 규칙상 rooms만 열림.
   꺼림칙하면 저장소를 Private로).
2. https://vercel.com → GitHub 연동 → **Import** → 프레임워크 "Other", 빌드 설정 없음 → Deploy.
3. 나온 주소(예: `https://logistic-exchange.vercel.app`)를 태블릿 북마크에 등록.

## 3. 게임 규칙 요약

- 모둠(투자회사) 6개(2~8 설정 가능), 시작 자본 **100코인**
- 종목 6개, 시작가 **10.0코인**: 🚚트럭 🚆철도 🚢선박 ✈️항공 🛸드론 🛢️파이프라인
- 10라운드. 매 라운드 **뉴스 3장 동시 공개** — 진짜 1장 + 더미 2장
- 매매 창 200초, 정수 주 단위, 공매도·수수료 없음
- **매매마다 ①진짜 뉴스 선택 + ②이유 10자 이상 필수** (관망도 이유 필요)
- 가격 변동 = 현재가 × (1 + %/100), 소수 첫째 자리 반올림
- 최종 자산 = 현금 + 보유주 × 현재가

## 4. 수업 진행 (45분)

규칙 4분 → 10라운드 × 약 3분 → 최종 결과·성적표 6분 → 정리 4분
("수단마다 무너지는 조건이 다르다 — 그래서 물류는 수단을 섞는다" → 3차시 예고)

교사 조작 순서 (라운드마다):
**[라운드 시작]** (뉴스 3장 + 60초) → (자동/수동) **[매매 마감]** → **[시장 공개]** → **[다음 라운드]**
실수했으면 **[되돌리기]** (1단계).

## 5. 오프라인 폴백 (뉴스 코드 모드)

- Wi-Fi 장애 시 학생 화면에 🔴 배너 + 코드 입력란이 자동으로 나타난다.
- 교사 화면 상단에는 **라운드 코드 `R-1`~`R-10`** 이 항상 표시된다.
- 학생: 매매 확정 → 교사가 시장 공개할 때 부르는 코드(예: `R-3`) 입력 → 로컬에서 가격 변동·정산·해설 표시.
- 자산은 구두로 교사에게 → 교사 화면 [자산 수동 입력]란에 기록 (오프라인 진행 모드일 때 표시).
- 재연결되면 학생 태블릿의 자산이 서버에 자동 병합된다.
- 교사 컴퓨터마저 오프라인이면: config.js 없이도 [새 게임] → **오프라인 진행 모드**로 전체 수업 가능.

## 6. 사전 점검 체크리스트

- [ ] 교사 컴퓨터에서 방 개설 → 태블릿 1대 입장 테스트
- [ ] 오프라인 모드 전환 테스트 (Wi-Fi 끄고 코드 입력)
- [ ] 아래 라운드 코드 표 인쇄본 교사 소지 (최후 폴백: 교사가 뉴스를 읽어주고 코드를 부른다)
- [ ] 수업 후 교사 화면에서 [방 종료] (데이터 삭제)

## 8. 뉴스·수치 수정 방법

`game-data.js` 만 열면 된다:
- `GAME.roundSeconds` — 매매 창 시간 (기본 200초)
- `GAME.startCash`, `GAME.totalRounds`, `GAME.minReasonLen`
- `ROUNDS[n].real.deltas` — 종목별 등락 %
- `ROUNDS[n].dummies` — 더미 뉴스 교체 (dummies[0]=근접, dummies[1]=원거리)

## 9. 다른 수업 게임에 재사용하기

`realtime.js` 는 게임 종류와 무관한 방/모둠 공통 모듈이다.
새 게임은 `RT.createRoom("쓰레기경매장", {...})` 처럼 `meta.game` 값만 바꿔
`rooms/{code}/state`, `rooms/{code}/groups/{gid}` 구조를 그대로 쓰면 된다.

## 데이터 모델 (Firebase RTDB)

```
rooms/{roomCode}/
  meta:  { game:"transport-stock", createdAt, teacherToken, groupCount, status }
  state: { round, phase:"lobby|preview|trading|locked|revealed|finished", timerEnd, prices:{truck:10.0,…} }
  groups/{groupId}: {
    name, pin, cash, holdings:{truck:3,…}, confirmed,
    trades:{ [round]: { pick, trades:{…}, reason, at } },
    history:{ [round]: assetAfter }
  }
```

- phase 전이는 교사 화면 버튼이 유일한 트리거. 학생 화면은 `state.phase` 를 구독해 자동 전환.
- 방은 24시간 후 자동 정리(다음 방 개설 시) + 교사 [방 종료] 버튼.
